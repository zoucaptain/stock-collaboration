## 📚 两大并列核心逻辑

| ID | 命名 | 灵魂 | 状态 |
|---|---|---|---|
| **L_core** | **三句诀操作法**（Three-Line Trading Doctrine）| "用上证指数做择时 / 用行业板块找主线 / 主线里抓龙头" + "大势不好少出手，主线不对不参与" | 🆕 |
| **L_resonance** | **5 条件共振选股法**（Five-Condition Resonance）| 5 指标共振才出手（实战严标准）| ✅ 已存在 |

---

## 🎯 两逻辑的关系（**并列，不是串联**）

```
                  ┌──────────────────────────┐
                  │ L_core 三句诀操作法        │ ← 操作哲学：什么时候动/不动
                  │ (5 句话灵魂)              │
                  └──────────────────────────┘
                              并列（不是 L_core 调用 L_resonance）
                              而是两个独立维度
                              各自解决不同问题
                              ↓
                  ┌──────────────────────────┐
                  │ L_resonance 5 条件共振    │ ← 选股技术：动哪只
                  │ (选股法)                  │
                  └──────────────────────────┘
```

**关系**：
- **L_core** 解决的是"**该不该动**"（大势 + 主线 + 龙头 + 空仓哲学）
- **L_resonance** 解决的是"**动哪只**"（5 指标共振找具体买点）
- **两个并列**，不是 L_core 包含 L_resonance，也不是 L_resonance 包含 L_core

---

## 🔑 命名规范（5 条铁律）

1. **直接反映灵魂**（一看名字就知道解决什么问题）
2. **动词在前**（Doctrine / Resonance = 行动导向）
3. **不超 8 个字**（OpenClaw 快速调用）
4. **用户原话驱动**（每条逻辑都能在用户对话中找到出处）
5. **不强行拆解**（用户的原话是 1 个灵魂就合并为 1 个，不要硬拆成 N 个）

---

## 🚀 OpenClaw 调用协议

**两个逻辑是并列的，OpenClaw 根据决策场景选一个或两个都用**：

- **判断"该不该动"** → 调 L_core
- **判断"动哪只"** → 调 L_resonance
- **完整决策** → 两个都用（先 L_core 定该不该动，再用 L_resonance 找具体买点）
